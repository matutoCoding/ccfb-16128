# 球道油型与油面消耗推演系统

浏览器内运行的保龄球道油型管理与油面消耗推演系统。TypeScript + WebGL2（自写着色器）+ IndexedDB，无 UI 框架依赖。

## 启动

```bash
npm install
npm run dev      # 开发服务器（默认 http://localhost:5180）
npm run build    # 类型检查 + 生产构建到 dist/
npm test         # 核心数值校验（11 项）
npm run bench    # 12 道 × 40 局性能基准
```

首次打开自动播种内置数据：长/短油型各一套、48 条球道（自家 24 + 外包 3 馆各 8）、6 球、8 打法、16 球员、打满 40 局共 3840 球的比赛记录。

## 六个页面

| 页面 | 功能 |
| --- | --- |
| 油型库 | 39 板 × 每英尺 load 录入，去程/回程分设，自动算总油量与油型长度，导入打油机 CSV/JSON，打印油型说明 |
| 球道档案 | 木质/合成，39 板高低差(mil)与磨损，侧坡重力带球 |
| 球与打法 | 球的粗糙度/核心/重量；打法的球速/转速/轴倾角/出手板位，左右手 |
| 油面推演 | GPU 浮点纹理逐球迭代，0~40 局滑条回放，打干轨道/后段带油可视化，同球第 1/30 局路径叠加，三路数值校验 |
| 比赛跟踪 | 按道按局录球员，左右手混合不对称消耗，下一轮重新过油建议 |
| 设置 | 物理参数滑条、重新过油阈值、GPU 能力检测、数据重置 |

## 两条硬指标如何保证

### 1. 板级油量误差 < 1%

每个接触格一次出手的油量变化由**同一套公式**驱动三条实现路径：

```
吸走  absorb_c = oil_c × 吸油率 × 横向权重
吐出  deposit_c = 后段(≥38ft)按横向权重分摊(总吸油 × 吐油比例)
净变  Δ_c = deposit_c − absorb_c
```

- **路径 A 网格权威** `src/core/oil-depletion.ts: applyShotGrid` —— 逐格更新 480×39 油网格
- **路径 B 独立公式累加器** `accumulateBoardLoss` —— 按"接触带宽 × 吸油率"逐球逐板累加净损失，不回读整张表
- **路径 C GPU 着色器** `src/webgl/oil-sim.ts` —— R32F 纹理 ping-pong，片元着色器逐格复用同一公式；每局仅回读一次校验，不逐球回读

关键设计：接触带在 CPU 侧确定性栅格化（每个油纹理行枚举中心列 ±1，横向权重 0.15/0.7/0.15 行内和恒为 1），CPU 与 GPU 实例化复用同一份枚举结果，从根上消除两端几何分歧。

实测最大板级相对误差 **0.000137%**（阈值 1%，余量四个数量级）。`npm test` 逐球（320 球）和终局各做一次三路比对。

### 2. 40 局推演 5 秒内

- 油面全程驻留 GPU 纹理，逐球只上传接触带实例（每球约 300~900 个格），不回 CPU 重算整表
- CPU 单道 40 局（320 球，含 41 张快照）实测约 **100~120ms**；12 道 3840 球合计约 1.2s
- 浏览器端含 GPU 往返实测 **~200ms/道**，远低于 5s 预算

## 油网格定义

- 横向 39 列（每块板一列），纵向 480 行（60ft × 8 行/英尺），单元 1.5in
- 打油机 1 load 标定为 50 µL，每英尺负载均摊到该英尺 8 行
- 油量单位 µL/格；纹理用 R32F 浮点，需 `EXT_color_buffer_float`（设置页自动检测）

## 物理模型要点

- 局部摩擦 = 干/油摩擦按油量双曲线平滑混合，油多摩擦小
- 勾球力 ∝ 转速 × 轴倾角因子 × 球速因子 × 球种 hookRating，需摩擦牵引，油区自然滑行
- 三段（滑行/转弯/滚动）由横向速度占比与转折点在线判定
- 板级高低差 → 横向坡度 → 重力侧加速度，把球带向低侧
- 球道 3D 视图默认做 2.6× 横向展示展宽（真实宽长比 1:18，等比投影下 39 板差异不可读），可一键切回真实比例；展宽只影响视觉，不改纹理与物理
